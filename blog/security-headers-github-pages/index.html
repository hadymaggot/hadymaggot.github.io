Security Headers di GitHub Pages: Apa yang Bisa dan Tidak

2026-11-16 4 menit baca SecurityWebCloudflare

GitHub Pages praktis untuk situs statis, tapi Anda tidak bisa mengatur header respons sendiri. Itu membatasi kontrol keamanan yang bisa dipasang.

Yang tetap bisa dilakukan

  • HTTPS dipaksa lewat pengaturan Pages.
  • CSP lewat tag meta (<meta http-equiv="Content-Security-Policy">). Berguna, tapi tidak mendukung frame-ancestors, report-uri, maupun sandbox.
  • Hindari inline script dan style supaya CSP yang ketat bisa dipasang kelak.
  • SRI (integrity) pada script dan stylesheet dari CDN.
  • /.well-known/security.txt berisi kontak pelaporan kerentanan dan tanggal Expires (RFC 9116).
  • robots.txt dan sitemap.xml di root, bukan di subfolder.

Kalau butuh header sungguhan

Pakai custom domain dan taruh proxy seperti Cloudflare di depannya, lalu tambahkan header (HSTS, X-Content-Type-Options, Referrer-Policy, Permissions-Policy, CSP lengkap) lewat aturan transformasi respons.

Verifikasi

Jangan percaya konfigurasi, periksa responsnya. Audit header dan TLS dari luar secara berkala, dan catat hasilnya agar regresi terlihat.
